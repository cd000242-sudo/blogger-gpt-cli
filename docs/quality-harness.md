## 2. 점수 밖 — 발행 전 수정만 (src/core/final/pre-publish-fix.ts)

점수에는 안 들어가고, 걸리면 AI 가 그 구간만 다시 쓴다. **호출 상한 1회** (사장님: 두 번 이상 금지).

## 4. 못 재는 것 — 사람이 읽어야 한다

오늘 10편을 실제로 읽고 확인한 것. **점수 94인 글에서도 전부 보였다.**

| 무엇 | 왜 못 재나 | 돈과의 관계 |
|---|---|---|
| 제목 ↔ 본문 **범위** 일치 | 수치 약속은 title-claim-check.ts 가 봄 ("9월 30일" 이 본문에 있나). 주제 범위("상품별 비교" 인데 한 상품만)는 못 봄 | 제목 보고 들어와 다른 글이면 그대로 나감 |
| FAQ 가 질문에 정확히 답하나 | 질문-답 대응을 안 봄 | 어제 평가에서 실제로 걸림 |
| 사실이 **맞는가** | 밀도만 잼, 진위는 안 봄 | 돈 걸린 글에서 틀리면 신뢰 끝 |
| 결론 박스가 답을 다 줘서 스크롤 유인이 없나 | 구조 검사 없음 | **광고 수익과 직결** — 답 얻고 나가면 광고를 안 본다 |
| 지역 사례를 전국처럼 쓰나 | 지역명 빈도만 셀 수 있음 | 다른 지역 독자가 기한을 놓친다 |
| 광고가 들어갈 문단 길이 | 없음 | 자동광고는 긴 문단 사이에 붙는다 |

## 5. 오늘 실측 — 10편 (2026-09-05, gpt-5.6-terra)

## 6. 오늘 잡은 검사기 오탐 — 5건

전부 "없는 결함을 만들거나, 있는 결함을 못 본" 종류. **검사기부터 검증할 것.**

1. `</blockquote><p>` 경계 누락 → 없는 「붙은 문장」 4건
2. `<br>` 미분리 → 있는 중복을 못 봄 (34 → 30 에서 멈춤)
3. 짧은 표본 되돌림 → 정당한 제거가 막힘
4. `법` 한 글자 → 「신청 방법」 을 제도 글로 판정, 6편 전부 -10
5. `<br>`→줄바꿈 → 한 문장 문단 85% (실제 21%)

## 8. 아직 못 재는 것

- 사실이 **맞는가** — 팩트체크 체인(퍼플렉시티·네이버 뉴스·기관 문서)이 따로 본다
- FAQ 가 답을 **피하는가** — "먼저 확인해 봐야 해요" 는 낱말이 맞아도 답이 아니다
- 지역 사례 → 전국 확장 — 사장님이 의도라 하셨으니 안 잰다

## 원칙

- 검사기는 지우지 않는다. 알려만 준다. 지우는 건 auto-repair 가 **기계로**.
- 정상 글이 걸리면 검사기를 의심한다 — 오늘 다섯 번 그랬다.
- 점수는 감점식 — 무엇 때문에 깎였는지 되짚을 수 있어야 한다.
- 점수가 높다 ≠ 읽기 좋다. **10편 뽑았으면 읽는다.**
