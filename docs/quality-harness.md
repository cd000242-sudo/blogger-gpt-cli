| 무엇 | 왜 못 재나 | 돈과의 관계 |

| 사실이 **맞는가** | 밀도만 잼, 진위는 안 봄 | 돈 걸린 글에서 틀리면 신뢰 끝 |

측정 열: `관점`(1인칭 판단 수) · `회피`(1,000자당). 문턱값 실측 보정(흐름 규칙 이전 5편): 회피 0.37~1.88 → 상한 2.5(10건 이상). 관점은 5편 전부 0 — 규칙 이전엔 필자의 판단이 한 문장도 없었다.

**경험** — 사장님: "이런 곤란한 상황 속에서 경험을 넣는 걸 원한다. AI 는 못 만들지만 우리는 만들 수 있게."
AI 는 경험을 만들 수 없으니 **사람이 적은 것만** 쓴다. 화면의 「🧑 내 경험 메모」(v3.8.392, experience-block.ts)는 API 경로만 읽고 있었고 **에이전트 경로는 버리고 있었다** — 같은 블록으로 넘긴다. 메모가 없으면 검색자가 실제로 올린 질문을 인용해 "이런 상황이 실제로 있습니다" 로 곤란한 상황을 세우고 필자는 판단으로 반응한다. 겪은 척은 어느 경우에도 안 쓴다(2026-08 조사: AI 생성 체험은 역신호).

## 7-7. v3.8.661 — 흐름 규칙 뒤 5편(94 · 80 · 88 · 100 · 76)을 읽고

**척추가 생겼다.** 다섯 편 모두 서론이 독자의 질문으로 끝나고(햇살론·대출은 검색자의 실제 질문을 인용해 열었다), 절마다 근거 붙은 판단이 붙고, 결론 첫 문장이 서론 질문에 답한다. 관점 0 → 5, 회피 0.32~1.46. 규칙 이전의 같은 키워드 5편과 나란히 읽으면 차이가 분명하다.

그래도 읽으니 다섯:
1. "…때문입니다></p>" — 모델이 흘린 '>' 하나 → `repairStrayBrackets`
2. "9·3 노동부 지침" → 소제목 "3 노동부 지침과 …" (3회 재현) — 코드 정규식이 아니라 **모델이 "9·" 를 번호로 알고 뗀다** → 제목의 날짜 접두어를 되돌린다 + 프롬프트에 "날짜는 번호가 아니다"
3. 소제목 없이 평문으로 늘어놓은 Q/A — h3 만 보던 `inline-faq` 가 놓쳤다 → 물음표로만 끝나는 짧은 문단 3개 이상이면 잡는다
4. 답 박스 질문 자리에 60자 넘는 서술문 → 키워드 질문으로 대신
5. "제 판단은" 이 절마다 똑같이 — 말머리를 바꿔 쓰게 한다

## 7-8. v3.8.662 — 깊이와 목소리 (src/core/final/depth-voice.ts)

사장님(2026-09-06): "난 여기에 인생을 걸었어 … 100점까지 글의 깊이와 목소리를 끌어올려줬으면 해" · "반드시 100점은 거짓이겠지, 근접하게"

100점은 보장하지 않는다. 미는 목표는 둘: **읽어서 잡히는 결함 0인 회차**, **판단에 조건·행동이 있는 글**.

| 지렛대 | 무엇 | 호출 |
|---|---|---|
| 자료가 되풀이하는 수치 | 생성 로그마다 "자료가 되풀이하는데 본문에 없음: 14.7%, 5%, 120만원…" 6개씩. 생성 **뒤**에만 세고 있었다. 생성 **전**에 값을 출처 문장째 넘긴다 | 0 |
| 판단 = 조건 + 행동 + 이유 | "메모해 두는 쪽입니다" 는 관점이 아니다. 프롬프트에 정의하고 `stance-shallow`(-6) 로 잰다 (판단 3개 이상 중 절반 미만이 조건·행동을 갖추면) | 0 |
| 절의 역할 | 상황 정의 → 갈림길 → 예외·함정 → 사례·수치 → 결정. 뒤 절은 앞 절 위에 올라선다 | 0 |
| 표 | 글 전체 3개 이하, 비교가 있을 때만, "누구에게 맞는지" 열 습관 금지. `table-template`(-4) | 0 |
| 곁가지 절 | 소제목 계획 프롬프트에서 제목의 독자에게 필요 없는 절 금지 | 0 |
| 1회 자가 수정 | no-stance · deferral-flood · stance-shallow · inline-faq 를 고칠 대상에 넣는다 — 기존 1회 한도 안에서 | ≤1 |

측정 열: `판단조건`(조건·행동 갖춘 판단 / 전체).

검사기 오탐 9번 — 661 에서 "판단 말머리를 바꿔 쓰라" 고 하자 모델은 "…쪽입니다 / …편이 맞습니다 / …맞다고 봅니다" 로 판단을 적었는데, 1인칭만 세던 검사가 다섯 편 전부 "판단 0" 이라 하며 -6 씩 깎았다. 판단 어미도 판단이다. 문장 단위로 센다 — "제 판단은 … 쪽입니다" 는 표현이 둘이어도 판단 하나다.

## 7-9. v3.8.663 — 깊이·목소리 규칙 뒤 5편(90 · 68 · 96 · 74 · 74)을 읽고

**된 것**: 곁가지 절(나스닥) 사라짐 · 자료 수치가 본문에 들어옴(마이너스통장 연 6.96%→대환 조회 11.9%, 약 200곳, 90·45거래일) · 결론이 "오늘 할 일" 로 닫힘 · 절마다 판단.
**안 된 것 다섯**:
1. 판단을 "판단이 타당합니다 / 편이 낫습니다 / 쪽이 맞습니다" 로도 닫는데 검사가 또 못 셌다 (오탐 10번) → 판단 어미를 넓게 센다
2. 되풀이 수치가 **무관해도** 들어갔다 — 대출 갈아타기 글에 삼성전자 사내 대출(5억원·1.5%)이 세 번 → 주제 낱말 둘 이상 든 문장의 수치만 넘기고, "주체가 다른 곳의 수치는 쓰지 않는다" 를 못 박는다
3. h2 "은행 심사 거절 뒤 자주 묻는 질문" — 절 제목에 FAQ 를 박고 Q/A 를 늘어놓았다. h3 만 보던 검사가 놓쳤다 → h2 도 본다, 질문으로 시작하는 문단도 센다
4. 표 4~6개 — "최대 3개" 를 시켜도 안 지킨다 → 코드가 숫자 적은 표부터 빼서 3개까지
5. H2 하나에 H3 둘 → 12,040자 → 분량 6,000~9,000자, H3 는 절당 하나가 기본
그리고 성과급 글은 660 에 있던 서울행정법원 판결(225일·11개월)을 이번엔 못 실었다 — 자료가 회차마다 달라서 생기는 편차. 근거 수집이 다음 지렛대다.

## 8. 아직 못 재는 것

- FAQ 가 답을 **피하는가** — "먼저 확인해 봐야 해요" 는 낱말이 맞아도 답이 아니다

## 원칙

- 검사기는 지우지 않는다. 알려만 준다. 지우는 건 auto-repair 가 **기계로**.
- 정상 글이 걸리면 검사기를 의심한다 — 오늘 다섯 번 그랬다.
- 점수는 감점식 — 무엇 때문에 깎였는지 되짚을 수 있어야 한다.
- 점수가 높다 ≠ 읽기 좋다. **10편 뽑았으면 읽는다.**
