# CTA 자라는 시드 — 기관 이름 → 실주소 레지스트리 (v3.8.706)

## 왜
2026-09-07 실측: 서로 다른 주제 15개를 편집기 "CTA 다시 생성" 배선 그대로 돌렸더니
**맞음 6 · 약함 3 · 틀림 6**. 틀린 6개의 원인은 네 가지였다.

| # | 원인 | 실측 사례 |
|---|------|-----------|
| ① | AI 가 기관 **이름**을 맞게 정했는데, 후보가 **그 기관 도메인이 아니어도 감점이 없다** | 정부24 → 금천구청 페이지 · 동물보호관리시스템 → 부산시 페이지 · 아이사랑 → 서울시 시설 페이지 |
| ② | 주제어 판정이 느슨(≤4 토큰 중 절반) → **같은 기관의 다른 제도 페이지**가 통과 | 월세 세액공제 → 교육비 세액공제 페이지 · 청년도약계좌 → 청년미래적금 페이지 |
| ③ | 행동이 없는 주제(레시피)에서 AI 가 억지로 기관을 지목 | 김치찌개 → 식품안전나라 게시글 |
| ④ | host-trust 가 `.go.kr/.or.kr` 밖의 공공 포털을 unknown-host 로 버림 | 비짓제주(visitjeju.net) 전부 제외 |

공통 뿌리: **AI 가 정한 이름을 도메인으로 바꾸는 길이 카탈로그(198곳) 하나뿐**이고,
15주제 중 9곳이 카탈로그에 없었다. 사장님: "이러한 시드가 방대해야 되지 않니?"

## 원칙 (바뀌지 않는 것)
- 주제→목적지를 코드에 박지 않는다. AI 가 **이름**을 정하고, **검색**이 주소를 찾고, **게이트**가 검산한다.
- 주소를 손으로 치지 않는다. 시드는 **이름 목록**만 손으로 적고, 도메인은 **실측(검색+접속 확인)** 으로 채운다.
- 발행을 막지 않는다. 레지스트리가 비어 있어도 예전 경로 그대로 돈다.

## 무엇을 만드나
```
src/cta/agency-registry.ts   이름→호스트 사전. 조회(lookup) · 실측 해석(resolve) · 학습(learn)
src/cta/agency-seed.ts       scripts/cta-agency-bootstrap.js 가 실측으로 생성한 시드 (손으로 고치지 않음)
~/.blogger-gpt/cta-agency-registry.json   발행하며 새로 알게 된 기관 (userData 에 저장 · 자란다)
```

### 해석(resolve) 절차 — AI 호출 0회
1. `lookup(name)` — 학습분 → 시드 → 기존 카탈로그(name-to-url) 순으로 본다.
2. 없으면 `"${이름} 홈페이지"` 로 웹문서 검색. 노조·채용관·위키·단축링크·국회 상임위(`*.na.go.kr`) 도메인, 네이버TV·유튜브 같은 플랫폼,
   제목이 뉴스·채용·블로그인 결과는 뺀다. "X 홈페이지 바로가기 (url)" 중계 글도 뺀다 — 단, 제목에 적힌 **다른** 주소는 그 호스트의 표(hinted)로 받는다.
   이름은 **앞뒤 글자를 따지지 않고** 찾는다 — "대검찰청"·"한국도로교통공단"·"TS한국교통안전공단"은 검찰청·도로교통공단·한국교통안전공단이다.
   (앞 글자 경계를 세웠다가 이 넷을 전부 놓쳤다. "과학기술정보방송통신위원회" 같은 남의 이름은 호스트로 턴다.)
3. **등기 도메인(apex)별** 점수 — license.korcham.net · cert.korcham.net · www.korcham.net 은 한 집이다.
   결과 제목에 이름이 있으면 +2(이름으로 시작 +1) · 홈 모양 주소 +1 · 제목이 이름 그 자체인 홈 +2 · 공공 도메인 +1 · 중계 글 표 +2.
   홈 모양 = `/`, `/portal`, `/www/main.do` 꼴. 쿼리가 붙은 주소(`?p=397`)와 숫자 한 마디(`/162`)는 글이다.
   "이름 그 자체" 에는 기관 꼬리말을 뗀 꼴("국민건강보험" ← 국민건강보험공단)과 지자체의 "청"("강원특별자치도청")도 든다. 교육청·의회는 아니다.
   한 집에 홈이 여럿이면 등급 순(제목이 이름 **전체** 3 · 이름의 한 조각·꼬리말 뗀 꼴·"청" 꼴 2 · 제목 첫 마디가 이름 1 · 홈 모양만 0) → 뿌리에 가까운 주소(www·등기 도메인 뿌리) 순으로 **최대 셋을 차례로 연다**.
   전체(3)가 조각(2)보다 앞서는 까닭: 국토교통부 실거래가 공개시스템은 "국토교통부" | www.molit.go.kr(조각)이 아니라 "국토교통부 실거래가공개시스템" | rt.molit.go.kr 이다 — 뿌리 우선 규칙(아래)이 같은 등급끼리만 뿌리를 고르므로, 등급을 나눠야 실거래가 화면이 부처 홈에 밀리지 않는다.
   고용보험은 ei.work24.go.kr("고용보험 - 고용24", 등급 1)이지 www.work24.go.kr("고용24")가 아니고, 한국공항공사는 park.airport.co.kr(주차)이 아니라 www.airport.co.kr 이다.
   **제목이 이름 그 자체인 홈은 점수보다 앞선다** — "강원특별자치도청" | state.gwd.go.kr 가 교육청 화면 다섯보다 먼저다.
4. 후보 1~3등의 홈을 **실제로 열어** 확인한다. **열리지 않는 홈은 어떤 규칙으로도 받지 않는다**
   (강원특별자치도 → office365.gwe.go.kr 을 제목 일치로 받았던 실측 — 독자를 죽은 주소로 보낸다). 받는 경우:
   ① 홈 `<title>` 에 이름 ② 본문 언급 + 제목 일치 2건 ③ 제목이 이름 그 자체인 홈, 또는 **사이트 뿌리** 홈 주소가 결과에 있고 제목 일치 2건
   ④ 중계 글 둘 이상이 같은 주소를 적었다(크레딧포유 → credit4u.or.kr — 기관 화면 제목엔 이름이 없다).
   ⑤ **이름이 바뀐 서비스** — 후보가 없거나 다 떨어진 뒤 마지막으로: 검색이 한 집을 **과반(4건 이상)** 으로 가리키는데 그 집 제목 어디에도
   이 이름이 없고(있었으면 위에서 이미 열어 보고 거른 후보다 — 보도자료 많은 금융위를 어카운트인포로 되살리지 않는다), 어느 제목이든 이름과
   **네 글자 이상 이어** 겹치며("동물보호"), 사이트 뿌리 홈이 결과에 있고 열리며 기관 도메인이거나 본문에 이름이 있다.
   동물보호관리시스템 → animal.go.kr("국가동물보호정보시스템", 7/9건) · 산업통상자원부 → motir.go.kr("산업통상부", 6/9건) ·
   한국산업안전보건공단 → kosha.or.kr("안전보건공단", 4/5건) 실측. "금융민원센터"를 금감원 신고센터 글이 과반으로 채워도 "금융"·"센터" 두 글자씩이라 남이다.
   다섯 다 떨어지면 null. **못 찾음이 오답보다 낫다** — null 은 옛 경로로 가고, 오답은 preferredHost 가 엉뚱한 곳을 가리킨다.
   - 열린 홈 여럿 중 이름이 보인 홈을 고른다 — 나라장터는 "나라장터" | bddm.g2b.go.kr(빈 화면)이 아니라 www.g2b.go.kr("나라장터")이다.
   - 이름은 하위 도메인이 확인해 줬어도 **뿌리 홈(www·apex 의 `/`)이 열렸으면 뿌리를 적는다** — cert.korcham.net(원산지증명센터)·
     jodal.koreapost.go.kr(조달센터)·onestop.khug.or.kr(모바일HUG)이 이름을 보여줬지만 집은 www 다(뿌리 제목은 EUC-KR 로 깨지거나 JS 라 비어 있다).
     단, 검색 제목이 이름을 앞세운 홈의 등급(ei.work24.go.kr "고용보험 - 고용24" = 1)이 뿌리("고용24" = 0)보다 높으면 그 홈이 집이다.
   - 뿌리 홈이 결과에 있는데 **안 열렸으면** 이름만 달린 하위 홈(등급 3 미만)으로 대신하지 않는다 — 한국장애인고용공단이 www.kead.or.kr(Node 에서 안 열림)
     대신 "한국장애인고용공단 고용개발원" | edi.kead.or.kr 로 시드에 적혔던 실측. 시드는 한 번 적히면 앱이 다시 풀지 않으니 null 로 두고 앱이 크로미움으로 배우게 한다.
   - ③ 의 "홈 주소가 결과에 있고"는 **사이트 뿌리**(`/`·`/main.do`)라야 한다 — 하위 사이트(gyeonggi.work.go.kr/icheon/main.do 이천일자리센터)만
     나온 호스트는 그 기관의 집이 아니다. 워크넷은 이 규칙 덕에 중계 글 둘이 가리킨 고용24(work24.go.kr)로 간다.
     열린 홈 중 사이트 뿌리면 어느 것이든 된다 — 전자소송은 www.scourt.go.kr/portal/main.jsp(깨진 제목)가 아니라 ecfs.scourt.go.kr/(빈 화면)이다.
   - 적는 주소는 **검색이 준 깨끗한 주소**다 — 최종 주소엔 세션 토큰이 붙는다(www.g2b.go.kr/?bodyDataKey=…, ;jsessionid=…). 다른 집으로
     옮겨 갔을 때만 옮겨 간 주소를 적는다.
5. 통과하면 학습 파일에 적는다. 다음 글부터는 검색 없이 바로 쓴다.

### 홈을 여는 방법 — `src/cta/page-fetcher.ts` 한 곳
관공서 홈은 브라우저에서는 열리는데 Node `fetch` 로는 안 열리는 것이 많았다(2026-09-08 실측):
- 국토교통부·법무부·경찰청·외교부·이파인·세움터 — 쿠키를 심고 **같은 주소로 307** 을 돌린다. `redirect:'follow'` 는 쿠키를 안 들고 가서 "redirect count exceeded".
- 한국소비자원·E-Gen·국가교통정보센터 — 중간 인증서를 안 보낸다(UNABLE_TO_VERIFY_LEAF_SIGNATURE). 브라우저는 OS 인증서 저장소로 메운다.
그래서 발행·편집기·시드 생성·측정기가 **한 페처**를 쓴다: 앱 안에서는 크로미움(`electron.net.fetch` — 쿠키·OS 인증서)으로,
스크립트에서는 Node 로 `redirect:'manual'` + Set-Cookie 를 들고 따라간다(최대 10홉). 시드 생성·측정 스크립트만 **그 프로세스에서** 인증서 검증을 끈다(공개 HTML 제목만 읽는다).
Node 스크립트가 못 연 곳(예방접종도우미·국립공원공단·금융결제원·한국장애인고용공단 — 구식 TLS·시간 초과)은 시드에서 빠지고, 앱이 발행하면서 크로미움으로 배운다.

### 판정에 어떻게 쓰나
- **host-trust**: `trustedHosts` 옵션 — 레지스트리가 확인한 호스트는 TLD 와 무관하게 통과(④).
- **regenerate / 발행 2단계**: 후보를 "지목 기관 호스트 / 그 외"로 나눠 **기관 호스트를 먼저** 열어 본다.
  기관 호스트에 행동 화면이 없으면 → `"${이름} ${주제어}"` 로 한 번 더 검색 → 그래도 없으면 **그 기관 홈**(guide).
  다른 호스트의 깊은 페이지는 기관 호스트에 아무것도 없을 때만, 그것도 guide 까지만(①).
  **약한 기준** — AI 가 지목한 `site` 를 레지스트리가 못 풀면(금융민원센터처럼 이름이 아닌 것) 글 본문이 이름 부른 기관(`analyzeArticleContext().agencies`
  앞 둘)을 대신 푼다. 이때는 그 호스트를 먼저 보되 gate 의 `preferredHost` 로는 주지 않는다 — 다른 호스트의 **action** 은 기관 홈보다 앞서고,
  기관 홈은 다른 호스트의 guide 보다 앞선다. `site` 가 빈 옛 경로(AI 없음)에서는 안 켠다 — 기존 버튼을 지우지 않는다는 약속 ① 때문이다.
  하지정맥류 실손 → AI "금융민원센터"(못 풂) → 본문의 금융감독원 → fss.or.kr 실측.
- **destination-gate**: `mustHave` — AI 가 정한 "그 화면에 꼭 있어야 하는 낱말 1~3개". 없으면 action 으로 올리지 않는다(②).
  `preferredHost` — 다른 호스트면 action 으로 올리지 않는다(①).
- **smart-cta**: JSON 에 `mustHave` 추가. `site:"없음"` 을 **정식 판정**으로 승격(③) — 호출자는
  `resolveSmartCtaDecision()` 로 `none` 을 받아 외부 CTA 를 넣지 않는다. 기관 법인명보다 **독자가 쓰는 서비스 이름**을 우선하게 한다(이파인·아이사랑·비짓제주).
- **발행 1단계(AI 가 URL 을 직접 낸 경로)**: AI 가 함께 낸 `agency` 이름을 레지스트리로 풀어, URL 이 그 호스트가 아니면 demote(2단계에 기회).
