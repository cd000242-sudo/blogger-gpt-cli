# AI 비서 (에이전트 탑재) 설계서 — v1

> 2026-09-09. 사장님 지시:
> "에이전트 자체가 붙으면어떠니?? 이미 클로드코드 안티그래비티 코덱스 등 에이전트사용이가능하니까
>  내앱 내부를 훤히알고 바이브코딩으로 직접만든 에이전트가 비서가되면 사용자들의 문제점도 알수있자나"
> "사용자들이 LLM구독이되어있다면 … API키로 비용을 지불안해도 할당량만있다면 사용이가능해"
> "사용자들이 문제가있거나 궁금증이있다면 나한테 묻는거나 다름이없어지지 — 어차피 난 너한테 또물어보거든"

## 0. 한 줄 정의

사장님이 클로드코드에게 묻던 역할을, **앱 안의 에이전트가 사용자에게** 해준다.
"발행이 안 돼요 / 이 버튼이 뭐예요 / 왜 이미지가 안 나와요"에 앱의 실제 상태(로그·설정)를 보고 답하는 비서.

## 1. 원칙 (설계에 못박는 것)

1. **에이전트 우선, 비용 0** — 로그인된 에이전트 CLI(claude → codex → gemini 순)가 기본 엔진.
   구독 할당량으로 돌므로 사용자 추가 비용이 없다. CLI 가 없으면 API 키 폴백(비평과 같은
   engine-selection 규칙), 둘 다 없으면 비서 패널이 에이전트 로그인 안내를 띄운다.
2. **근거 없는 답 금지** — 비서는 ① 지식 파일 ② 진단 스냅샷 안에서만 답한다.
   모르면 "이 부분은 제가 모릅니다 — [문제 신고]를 눌러 주세요"라고 말하게 프롬프트에 못박는다.
3. **자격증명 마스킹** — 진단 스냅샷에 키·토큰·비밀번호 값은 절대 싣지 않는다(유무만).
   로그 꼬리도 마스킹 필터를 통과시킨다. credential-logging 테스트 원칙 그대로.
4. **1단계는 읽기 전용** — 비서는 셸 명령을 실행하지 않는다. 앱 상태를 읽고 말로 안내만 한다.
   (행동은 2단계에서 화이트리스트 IPC 로만.)
5. **경량 호출** — `runAgentTextTask` 재사용(도구 없음, claude 는 `--max-turns 4`).
   지식+진단+대화 컨텍스트 합계 상한 24,000자. 대화 이력은 최근 6턴만 싣는다.

## 2. 구성요소 (1단계)

### A. 비서 지식 파일 — `electron/assets/assistant-knowledge.md`
- **빌드 때 생성**: `scripts/build-assistant-knowledge.js`
  - 입력: `docs/APP_ARCHITECTURE.md` 요약 + 기능별 사용법(탭·버튼 이름 기준) +
    "자주 나는 문제와 해결"(지금까지의 실측 사고 목록: 키 만료·세션 만료·이미지 폴백·
    업데이트·무료체험 쿼터 등) + 요금/라이선스 안내(leaderspro.kr/pricing).
  - 소스 코드는 싣지 않는다 — 비서에게 필요한 건 설계도면이 아니라 정비 매뉴얼이다.
  - 상한 15,000자. 넘으면 빌드가 실패한다(조용히 잘리면 지식이 반쪽이 된다).
- `npm run build` 사슬에 연결 + asar 에 포함.

### B. 진단 스냅샷 — main.ts `assistant:diagnostics` (내부 함수, IPC 겸용)
```
{
  version, platform(win/mac), packaged 여부,
  engines: { text: 현재 텍스트 엔진, image: 현재 이미지 엔진 },
  agents: [{ provider, status }],                  // 로그인된 CLI 목록
  keys: { openai: true/false, gemini: false, ... }, // 유무만. 값 절대 금지
  platforms: { tistory: 연결/만료, wordpress: ..., blogger: ... },
  recentLogTail: 마스킹된 최근 로그 120줄,
  lastFailure: 최근 실패 이벤트 요약(있으면),
}
```
- 마스킹: `sk-…`, `Bearer …`, `refresh_token=…`, 이메일, URL 쿼리의 key= 값 → `***`.
  마스킹 함수는 단위 테스트 필수(새는 패턴 1개가 사고다).

### C. 비서 호출 — main.ts `assistant:ask`
1. 엔진 결정: `loadAgentProfiles()` 에서 status ready 인 provider 우선(claude → codex → gemini),
   없으면 engine-selection 폴백, 둘 다 없으면 `{ needsAgent: true }`.
2. 프롬프트 조립: 역할("이 앱을 만든 개발자를 대신하는 비서") + 지식 파일 + 진단 스냅샷 +
   최근 대화 + 질문. 출력 형식: **답 → 근거(로그/설정 어느 줄) → 다음 행동(버튼·탭 이름)**.
3. `runAgentTextTask(provider, prompt, send)` 호출, 실패 시 API 폴백 1회, 그것도 실패면
   실패 이유를 그대로 돌려준다(조용히 비우지 않는다).

### D. 화면 — `electron/ui/modules/assistant.js` + 사이드바 항목 "🤖 AI 비서"
- 채팅 패널(오버레이): 말풍선, 입력칸, 엔진 배지("클로드코드 · 구독 할당량 — 추가비용 0").
- 프리셋 버튼 4개: "발행이 실패했어요" / "이미지가 안 나와요" / "이 기능 어떻게 써요?" /
  "지금 설정 점검해줘".
- 대화는 세션 메모리만(localStorage 저장 안 함 — 진단 내용이 남으면 안 된다).
- CLI 도 API 키도 없으면: 에이전트 로그인 안내 + 환경설정 Agent 탭 바로가기.

### E. 테스트
- 마스킹 단위 테스트(핵심) — 실제 유출 패턴 픽스처로.
- 배선 실존 테스트: IPC 등록 + UI 호출 + 사이드바 버튼 + 지식 파일 빌드 사슬 +
  "지식에 없으면 모른다고 한다" 프롬프트 문구.
- IPC 고아 가드(v3.8.701) 자동 통과 확인.

## 3. 이후 단계 (이번에 안 함)

- **2단계 — 손 있는 비서**: 화이트리스트 행동(설정 탭 열기, 재시도, 캐시 비우기, 재로그인 창 열기).
  비서가 "제가 열어드릴까요?" → 사용자가 버튼으로 승인.
- **3단계 — 문제 신고 순환**: 비서가 못 푼 문제 → [이 문제 신고] → 마스킹 진단 번들을
  GAS(오늘의 글감과 같은 통로)로 전송 → 사장님이 클로드코드로 분석. **동의 문구 필수.**
  사용자 문제가 곧 개발 백로그가 되는 순환.

## 4. 규모 추정 (1단계)

| 항목 | 파일 | 규모 |
|---|---|---|
| 지식 빌드 스크립트 | scripts/build-assistant-knowledge.js + 지식 원문 | 중 |
| 진단+ask IPC | electron/main.ts | 중 |
| 마스킹 모듈 | src/core/assistant/redact.ts | 소 (단위테스트 포함) |
| 비서 패널 | electron/ui/modules/assistant.js + 사이드바 | 중 |
| 테스트 | __tests__/ 2개 | 소 |

릴리스 규율(1릴리스 1위험)에 따라 **비서 단계만 단독 릴리스**로 낸다.
