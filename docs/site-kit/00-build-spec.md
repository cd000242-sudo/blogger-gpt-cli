# 사이트 구축 스펙 (범용)

> **주제 .md 하나를 넣으면 이 문서대로 사이트가 나온다.**
> 금융·법률뿐 아니라 라면·여행·게임 어떤 주제든 같은 뼈대를 쓴다.
> 2026-08-26 작성. 기준은 **이미 만들어 굴리고 있는 leadernam.com(CLAIMWISE)** 을 실측해 뽑았다.

```
[ 주제.md ]  ──▶  [ 이 스펙 ]  ──▶  [ 완성 사이트 + 어드민 ]
   무엇을            어떻게              무엇이 나오는가
```

주제 .md 는 **무엇을 다룰지**만 정한다(사이트명·카테고리·키워드·말투).
**어떻게 만들지는 전부 이 문서**에 있다. 그래서 주제가 바뀌어도 이 문서는 안 바뀐다.

## 1. 필수 체크리스트 — 이걸 다 통과해야 "완성"이다

검증 명령을 함께 적었다. **눈으로 보지 말고 돌려서 확인한다.**
`SITE` 는 대상 도메인으로 바꾼다.

| # | 항목 | 요구 | 검증 | CLAIMWISE 실측 |
|---|---|---|---|---|
| 1 | 페이지마다 고유 title | 모든 페이지가 서로 다른 `<title>`. 사이트명은 뒤에 붙인다 | 사이트맵 전 URL의 title 수집 → 중복 0 | ✅ |
| 2 | 페이지별 meta description | 홈·글·카테고리 **전부**. og:description 만으론 안 된다 | `curl -s $SITE \| grep 'name="description"'` | ✅ (2026-08-26 홈 누락분 수정 — 아래 2-1) |
| 3 | h1/h2 구조 | h1은 **정확히 1개**(글 제목). 본문은 h2, 하위는 h3. 건너뛰기 금지 | `grep -o '<h1' page \| wc -l` → 1 | ✅ (h1 1 / h2 5 / h3 13) |
| 4 | 모바일 반응형 | `viewport` 메타 + 가로 스크롤 0. 표·코드는 자체 스크롤 상자 | viewport 존재 + 360px 폭에서 가로 스크롤 없음 | ✅ |
| 5 | 이미지 alt | 모든 `<img>` 에 의미 있는 alt. 장식 이미지는 `alt=""` | `<img` 수 = `alt="` 수 | ✅ (4/4) |
| 6 | 읽기 쉬운 URL | 짧고 뜻이 보이는 주소. **한글 슬러그는 퍼센트 인코딩돼 길어진다** | 사이트맵 URL 길이·`%` 포함 여부 | ⚠️ **한글 슬러그** — 아래 6-1 참고 |
| 7 | canonical | 모든 페이지에 자기 자신을 가리키는 canonical 1개 | `grep -c 'rel="canonical"'` → 1 | ✅ |
| 8 | robots.txt | 봇 차단 없음 + 사이트맵 명시 | `curl -s $SITE/robots.txt` | ✅ |
| 9 | sitemap.xml | 글·페이지·카테고리 포함, 색인에 등록 | `curl -s $SITE/sitemap_index.xml` | ✅ |
| 10 | 내부링크 | 글마다 같은 사이트 글로 **최소 3개** | 글 페이지의 자기 도메인 링크 수 | ✅ (39개) |
| 11 | 카테고리 연결 | 모든 글이 카테고리 1개에 속하고 주소에 포함 | 고아 글 0 | ✅ |
| 12 | 관련 글 | 글 하단에 같은 카테고리 글 3~6개 | 관련 글 블록 존재 | ✅ |
| 13 | 깨진 링크 검사 | 내부·외부 링크 4xx/5xx 0건. **주기적 재검사** | 링크 수집 → HEAD 요청 | 🔁 자동 검사로 편입 |
| 14 | HTTPS 정상 | http → https **301**, 혼합 콘텐츠 0 | `curl -o /dev/null -w "%{http_code} %{redirect_url}" http://$SITE` | ✅ (301) |
| 15 | Googlebot 접근 | 본문이 **HTML에 그대로** 있어야 한다. JS로만 그리면 안 된다 | JS 끈 상태로 본문 문자열 존재 | ✅ |

### 2-1. 홈 meta description — 코드로 넣을 수 있다

워드프레스 기본 REST(`/wp/v2/pages`)에는 Yoast 설명 필드가 **노출되지 않는다.**
그런데 Yoast 가 자기 네임스페이스에 일괄편집 엔드포인트를 열어 뒀다.

```bash
POST {SITE}/wp-json/yoast/v1/bulk_editor/update_search
{ "items": [ { "id": 5125, "meta_description": "..." } ] }
```

`seo_title` · `meta_description` · `focus_keyphrase` 중 최소 하나가 있어야 한다.
**신규 사이트 구축 단계에서 홈·카테고리 설명을 이걸로 한 번에 채운다.**
(2026-08-26 CLAIMWISE 홈에 적용해 실물 반영 확인)

### 6-1. 한글 슬러그 문제 — 결정이 필요하다

CLAIMWISE 의 실제 주소는 이렇게 나온다.

```
/documents/%ea%b0%80%ec%a1%b1%ea%b4%80%ea%b3%84%ec%a6%9d%eb%aa%85%ec%84%9c-...
```

브라우저 주소창에서는 한글로 보이지만, **복사하거나 공유하면 저 상태**가 된다.
- **한글 유지** — 국내 검색·클릭률에 유리하다는 견해. 다만 주소가 길고 지저분해진다
- **영문 슬러그** — `/documents/family-certificate-online/` 처럼 짧고 공유가 깔끔하다

**신규 사이트는 영문 슬러그를 기본값으로 한다.** 기존 사이트는 바꾸지 않는다 —
주소를 바꾸면 색인이 흔들리고 얻는 것보다 잃는 게 크다.

## 2. 사이트 구조 (주제와 무관하게 동일)

### 카테고리
- **5~6개.** 더 늘리지 않는다. 벤치마크한 사이트들이 전부 이 범위였다
- 이름은 한글, 슬러그는 영문
- 모든 글은 정확히 1개 카테고리에 속한다(다중 분류 금지 — 중복 콘텐츠 신호가 된다)

### URL
```
글        /{category}/{postname}/
카테고리   /{category}/
고정       /about/  /contact/  /privacy-policy/  /disclaimer/
```

### 필수 고정 페이지 4종
없으면 **애드센스 정책 위반**이다. 승인 자체가 안 난다.

| 페이지 | 반드시 들어갈 것 |
|---|---|
| 소개 `/about/` | 누가 왜 운영하는지, 어떤 기준으로 쓰는지, 저자 소개 |
| 문의 `/contact/` | 연락 수단(폼 또는 이메일) |
| 개인정보처리방침 `/privacy-policy/` | 쿠키·애드센스·분석도구 사용 고지 |
| 면책 `/disclaimer/` | "일반적 정보이며 개별 상담이 아님" |

### 글 한 편의 뼈대
```
① 결론부터 블록      질문 → 2~4문장 답 → 근거 기관·기준일   (v3.8.559)
② 서론
③ 핵심 요약표
④ 목차
⑤ 본문 (h2 4~6개 · 각 h2 아래 h3)
⑥ 관련 글 3~6개
⑦ 독자 확보 블록      즐겨 보는 출처 지정 + 팔로우 안내     (v3.8.560)
```

### 신뢰 신호 (YMYL 주제는 필수, 나머지도 권장)
- 저자 실명 + 소개 + `Person` 스키마
- `Organization` 스키마
- 글마다 작성일·수정일 표시
- 수치에는 출처 기관과 기준 시점 병기

## 3. 어드민 — 여기까지 있어야 판매할 수 있다

구매자가 **워드프레스 관리자에 들어갈 일이 없어야 한다.** 6개 화면.

| 화면 | 반드시 되는 것 |
|---|---|
| **대시보드** | 어제 수익(달러)·조회·RPM·발행 글·색인 수, 발행 큐, 상태 점검 |
| **글쓰기** | 제목·본문 편집, 이미지·표·링크, 카테고리·태그·예약, 검색 제목/설명, 근거 검사 |
| **글 관리** | 목록·필터(발행/예약/임시/오류), 글별 조회·수익·색인, 일괄 삭제·이동 |
| **스킨** | 테마 프리셋, 색·글꼴·크기·배치·로고, 광고 자리 on/off, **실시간 미리보기** |
| **카테고리·메뉴** | 이름·슬러그·순서·노출 |
| **설정** | 주제 .md 연결, 하루 발행 수, 말투, 외부 연결 상태 |

### 애드센스 연동 — 되는 것과 안 되는 것

**AdSense Management API v2** 로 구글 로그인(OAuth) 후 리포트를 읽어온다.

| 된다 | 안 된다 |
|---|---|
| 수익·조회·RPM 리포트 읽기 | 광고 설치·계정 개설 |
| 사이트·광고단위별 분해 | 애드센스 **승인**(사람이 받아야 한다) |
| 자동 동기화 | 당일 확정 수치(전일까지만 확정) |

**판매 시 반드시 고지할 것:** 애드센스는 사이트가 아니라 **계정에 붙는다.**
산 사람이 자기 애드센스로 다시 승인받아야 하고, 승인이 안 나면 수익은 0이다.

### 상태 점검 — 어드민이 자동으로 돌린다
위 체크리스트 15개를 **6시간마다 재검사**해 어드민에 표시한다.
이 화면이 곧 **판매 시 품질 증명서**가 된다.

## 4. 주제 .md 가 채우는 빈칸

이 스펙에서 주제마다 달라지는 건 아래뿐이다.

```yaml
사이트명:        예) 라면연구소
태그라인:        예) 끓이기 전에 보는 곳
도메인:
카테고리:        6개 (이름 + 영문 슬러그)
테마 프리셋:     푸드 / 금융 / 뉴스 / 건강 / 라이프 / 미니멀
말투:            친근·리뷰형 / 정중·정보형 / 전문·분석형
하루 발행 수:    2~3편
첫 30편 키워드:  발행 순서대로
YMYL 여부:       예/아니오 (예면 신뢰 신호 강제)
면책 문구:       주제에 맞게
수익 모델:       애드센스 + 제휴(있으면)
금지어:          주제별 위험 표현
```

## 4-1. 디자인 — 별도 문서에 실측해 뒀다

**이 자리는 오랫동안 비어 있었다.** 구조·SEO 는 적어 뒀는데 폰트·색·간격·애니메이션은
한 줄도 없었고, 벤치마크 사이트를 "WP + GeneratePress" 라고 적어 둔 것도 **틀렸다**(자체 테마다).

→ **[01-design-spec-the-edit.md](01-design-spec-the-edit.md)** — the-edit.co.kr 을
Playwright 로 열어 데스크톱·모바일 두 벌로 잰 실측서. 색 4개·타이포 표·컬럼폭 800px·
문단간격 30px·transition 22개·GSAP 핀 4개까지 값 그대로 들어 있고, 복사해 쓸 CSS 토큰이 §8 에 있다.

**두 문서의 역할이 다르다.**

| | 이 문서(00) | 디자인 실측서(01) |
|---|---|---|
| 무엇 | 구조·SEO·어드민 — **검색에 걸리기 위한 것** | 폰트·색·간격·모션 — **보기 위한 것** |
| 근거 | leadernam.com 실측 | the-edit.co.kr 실측 |
| 벤치마크를 따를까 | — | **디자인만 따르고 SEO 는 따르지 않는다** |

마지막 줄이 중요하다. the-edit 은 숫자 URL(`/87752`)·이미지 alt 방치·홈 h1 0개인데도 버틴다 —
**브랜드로 들어오는 트래픽이 크기 때문**이다. 검색으로 먹고사는 사이트는 그 여유가 없다.
실측서 §7 에 "배울 것 / 배우지 말 것"을 갈라 뒀다.

## 5. 완료 판정

아래가 **전부 통과해야** 완성이고, 팔 수 있다.

- [ ] 체크리스트 15개 전부 ✅ (자동 검사 통과)

- [ ] 모바일 360px 에서 가로 스크롤 0

**팔 목적이라면 여기에 하나 더:** 최소 6개월 수익 이력.
매각가는 *월 순익 × 24~40배*라서, 순익이 0이면 값도 0이다.
